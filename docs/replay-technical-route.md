# P6 2D 地图回放技术路线

日期：2026-10-15。状态：P6.0–P6.4已完成本机范围的实现/自动化验收；真实结果、失败历史与固定预算见 [实施记录](./replay-implementation.md) / [验收JSON](./replay-acceptance.json)。
用户指定仅使用现有 `dust2.dem` 作本次真实 DEM 验证；其他样本缺失不阻塞，未执行项如实保留。
原P6验收使用范围为本机个人、非商业开发/安装验证。用户于2026-10-16进一步明确将地图资源一并提交/推送，并扩展至Dust2、Inferno、Mirage、Ancient、Overpass、Vertigo、Nuke、Anubis、Train、Cache十图：13张PNG与10份原overview随仓库保存；第三方分发许可仍未确认的记录保留。
安装包、DEM、VPK和提取工具仍为本机产物，不随本次地图资源提交。
其他真实地图/个人DEM与旧golden缺失按用户限定范围不阻塞，未执行项不记PASS；所有地图版本匹配仍未确认。

## 1. 已确定的方向

- Windows x64 Electron 桌面端内的 2D 比赛回放，复用 React、TypeScript、Fluent UI v9。
- 官方雷达素材优先，配套 overview 坐标配置；维护环境准备地图资源，用户运行时不需要安装 CS2。
- DEM 在本地解析；独立回放采样 + 精确事件时间线 + Canvas 2D 展示，按回合加载。
- P6 不依赖账号、云端、P8 知识管线或 AI 服务，不实现 P7 热力图、3D、视线判断或战术评分。
- 当前开发机器未安装 CS2，不读取或扫描 Steam/CS2 安装目录。仓库的 DEM fixture 是独立测试材料，是否存在须在实施时检查。

## 2. 地图素材获取与管理

### 2.1 来源优先级

| 优先级 | 路径 | 使用方式与验证 |
| --- | --- | --- |
| 首选 | 从 Valve 的 Steam 游戏分发内容获取所需 VPK，再用开源工具提取雷达底图及 overview | 在维护/构建环境处理，不作为客户端启动或导入 DEM 的步骤；记录 depot/manifest、文件摘要和工具版本 |
| 验证与备选 | 社区从官方内容提取的版本包，如 `pnxenopoulos/awpy-data` | 固定 release/commit，核对实际文件、来源说明、清单与摘要，不直接依赖不断变化的 latest/main |
| 交叉核对 | `MurkyYT/cs2-map-icons` 的底图及原始 overview | 对照资源配对和坐标信息；同样固定版本，不把社区发布渠道称为 Valve 官方 API |

P6.0 已通过 DepotDownloader 文件列表定向获取固定 Valve depot/manifest 的 VPK 索引及所需六个分卷，并用固定版本 Source2Viewer 提取配套图片/overview；未安装或扫描 CS2。Source2Viewer 是开源提取工具，不是 Valve 官方工具。实际文件布局、体积、摘要及 Dust2 四区域配准结果见 [实施记录](./replay-implementation.md) 与 [资源清单](./replay-resources.json)；DEM 与底图版本匹配仍未确认。

资源必须保留来源与适用条款记录；开源提取脚本的许可不等于 Valve 素材的许可。若某来源无法证明其所提供资源的版本或来源，应降级或换源，不能补写“已确认”。是否可随安装包分发在资源验证阶段核实并记录。

### 2.2 地图资源包

- 每份地图资源应绑定地图标识、底图实际尺寸、overview 原文/归一参数、层级配置、来源版本、校验摘要与配准验证记录。
- 支持保留同名地图的不同版本，不按当下竞技地图池筛掉历史 DEM 所需地图。
- 雷达底图、overview、楼层配置必须配套。不能把不同 release 的图片与配置拼接后声称精确匹配。
- 已确认可分发的资源在维护阶段准备、随应用本地可用；默认回放不热链 GitHub，也不要求用户安装提取工具。资源获取失败不影响已有比赛报告。
- 实施时定义资源状态：版本匹配已确认、版本/配准未确认、资源不可用。地图名相同不代表版本一致；不能仅凭最新版本清单推断其匹配某个 DEM。
- 未确认匹配的地图最多显示明确标注的示意回放；缺少合法配套资源/坐标时保留事件浏览并解释不可用，不凭空生成底图。

## 3. 坐标映射与楼层

overview 的 `pos_x / pos_y / scale` 是坐标映射输入；`rotate / zoom / inset` 等字段含义及其对原始图片的影响需逐项核实，不能机械套用游戏 HUD 的变换。使用底图自然尺寸归一化，再统一处理画布缩放和设备像素比；玩家点位、朝向、炸弹与道具共用同一投影。

以多个分布在地图不同区域的独立可验证地标/事件检查配准，并覆盖坐标轴方向、尺度、边缘和朝向。不能只用转换函数的正反算证明地图对齐。缺乏真实配准证据时明确保留未验证状态。

多层地图优先读取资源的 `verticalsections` 与上下层底图，依据已验证的 Z 区间选择/标记楼层；提供手动层级切换。缺 Z、楼层阈值歧义和过渡区保留未知，不把多层玩家画成同层接触或据此判断支援。楼层规则与参数随资源版本管理，不在组件内硬编码一张地图的经验阈值。

P6 仅完成可核验的平面投影与层级展示，不需要 nav mesh 或 collision mesh。它们也不能用雷达图片代替，留待 P8 空间能力验证时独立处理。

## 4. 本地回放数据

### 4.1 采样策略

- 保留现有 `parseWithSpatial()` 对 Deep Review 的稀疏证据语义，新增显式回放采样能力；不把现有样本连线当作连续轨迹。
- 在正式回合窗口内请求固定频率状态，并保留必要的起止/生命周期及战斗/炸弹/已支持道具事件 tick。采样请求不越过不可靠的回合边界。
- 原生查询只能经 `dem-parser` 内部适配器执行。复用同一文件字节与基础 Match/事件查询，避免每名玩家、每个播放帧或每次拖动都重新解析 DEM；回放有独立采样预算，不削减既有证据覆盖。
- P6.0 比较候选采样率（例如 8/16/32 Hz）的误差、导入耗时、峰值内存、数据量与 seek 体验，再固定首版参数和预算。这些是待测选项，不是已验证性能。
- tick rate 不可靠时仍保留真实 tick，不编造秒数或正常倍速。未知/缺失字段为未知，零值仍为零；保留 requested/actual tick、来源和覆盖信息。
- 回放缓存按 DEM 内容身份、回放 schema、解析器/采样版本及地图资源身份隔离；首版以会话内有界缓存为基线，不顺带建设持久比赛历史。

### 4.2 时间与状态语义

- 区分采样位置、事件状态和显示插值。显示插值不是新增真实 tick，禁止回写 Analytics/Findings 或作为训练证据。
- 仅对同一连续有效片段内、两端有效的相邻位置/朝向插值；朝向采用经过验证的坐标约定与短弧处理。不跨缺失段、死亡/重生、断连或回合边界插值。
- 血量、存活、阵营、炸弹生命周期等按经验证的状态/事件更新，不对离散状态做平滑。同 tick 不制造 subtick 顺序；冲突按领域契约标歧义。
- 缺失段不无限沿用最后位置或假定玩家仍存活，显示断点/未知；生命周期不完整不能用其他玩家的位置行补齐。
- 明确处理 freeze、正式回合结束和回合后事件；回放窗口与现有 Timeline 的回合归属和时间起点保持一致，不混入热身或改变原始事件。
- 轨迹、投掷物飞行、烟火边界与闪光效果分别声明能力。首版只展示已证实的位置/生效点/生命周期；缺少飞行数据不画抛物线，缺少精确区域不画看似真实的烟墙或火区。
- P6 是全局比赛回放，必须标识观察视角；朝向箭头只表达记录的方向，不表示看到了敌人。后续 P8 的当时信息视图不能直接使用此全局展示状态。

## 5. 分包与进程边界

| 层 | 职责 |
| --- | --- |
| `dem-parser` | native 查询、回放采样及来源映射；不引入 UI/Canvas |
| `match-model` | 新增独立、可序列化的回放领域契约与覆盖语义；兼容既有 Match/Spatial，不把 DTO 放到 Electron 私有类型里 |
| `analytics / deep-review / findings` | 既有确定性逻辑保持不变，不从显示插值或 Renderer 获取事实 |
| Desktop Utility Process | 本地解析、构建/缓存回放片段；回放失败独立降级，不破坏成功的报告 |
| Main / preload | 管理回放会话、限额、取消和经过授权的分块请求；验证当前窗口/主 frame 与会话/回合归属 |
| `report-contract` / presenter | 版本化 JSON 展示元数据与按回合/时间块 DTO；不向 Renderer 传原生对象、文件路径、任意 fs 或全部 Match |
| Renderer | Fluent UI 控件和 Canvas 2D 投影/显示插值；不调用 parser、计算统计或推断新比赛事实 |

现有 worker 在报告返回后的生命周期必须先调查；实现受控的会话缓存与分块读取，避免简单假定现有导入流程已支持持久 worker。会话结束、重新导入、取消与窗口关闭必须释放资源；旧会话请求和异步返回不得污染新比赛。

优先按回合分块，超出预算的长回合再按时间分块；相邻块需保留必要的边界状态以支持有界插值。随机 seek 应能从目标块的状态基线恢复，不必从比赛开头重播事件。控制 IPC 大小和缓存上限，不一次传整场 JSON。具体 API/DTO、版本迁移和 worker 生命周期在 P6.2 设计并验证，不破坏已有导入与报告契约。

## 6. 播放与展示

- Canvas 2D 负责底图、玩家点位、朝向、选中玩家、炸弹及已支持的事件效果；静态底图与动态层按需复用。
- React/Fluent UI v9 负责播放/暂停、速度、回合选择、进度定位、楼层切换及覆盖说明。Canvas 的选手/事件信息也应有可访问的文字入口和键盘控制。
- 使用统一回放时钟，数据 tick 为权威，动画帧仅驱动绘制；暂停、seek 和切速应得到一致的目标状态，后台/丢帧后不靠逐帧累计制造时间漂移。
- 与既有 Timeline/Findings 的回合和证据引用联动，定位到同一比赛同一事件。保持原报告、时间线、分析和深度复盘可用，不擅自重新设计其布局。
- 首版无需引入 PixiJS、WebGL 或游戏引擎。若 Canvas 实测不满足预算，再提出有证据的改选方案。

## 7. 分阶段实施与验收

| 子阶段 | 交付物与通过条件 |
| --- | --- |
| P6.0 资源与可行性验证 | 固定合法可用的底图/overview 来源及版本，校验实际文件；Dust2 配准与回放采样试验，记录性能；在进入正式开发前固定资源、数据与交互验收预算 |
| P6.1 地图资源基础 | 版本化地图清单/装载、纯投影逻辑、资源缺失/未确认回退；Dust2 多点配准，Nuke 层级与边界验证 |
| P6.2 回放采样与传输 | 独立领域/展示契约、真实 DEM 采样、有界会话缓存及分块 IPC；随机 seek、一致性、缺失段、取消和清理通过 |
| P6.3 播放器与证据联动 | Canvas 播放、暂停、倍速、seek、回合/玩家/楼层切换，Timeline/Findings 联动；缺失数据和长回合可理解地展示 |
| P6.4 回归与安装验收 | 全链路与 Windows 安装版离线资源验证、性能实测及独立复核；同步实际状态和限制 |

Dust2 是首个可验证纵向切片，不把整个 P6 锁死到 Dust2。当前按用户扩图指令支持十图底图，Nuke/Vertigo/Train按配套overview处理双层。真实DEM gate仍按用户指定的单一Dust2范围执行；资源支持不改变 [fixture matrix](./demo-fixtures.md) 的历史强制样本规则，也不代表新增地图已完成真实配准。

具体验收至少覆盖：

1. 地图来源、版本、摘要、图片尺寸及多点配准可复查，未确认的地图有清晰状态；地图层级由已验证元数据控制。
2. 抽查真实玩家状态与精确事件，核对位置、朝向、阵营、存活及炸弹；覆盖同 tick、缺失、死亡/重生、回合边界，显示不超出证据。
3. 连续播放、直接 seek、跨块 seek 在同一 tick 得到一致离散状态；不跨缺失片段平滑，旧会话返回被忽略。
4. 测试多次导入、暂停/切速、取消、回放失败、关闭窗口及 worker 清理；受信 IPC 与沙箱边界保持。
5. 核心包相关测试、`pnpm typecheck`、`pnpm build` 和现有报告 golden 通过；测试新增边界，不通过改写旧数值/阈值逃避回归。
6. 实际 Electron 检查播放与原报告；相关 Windows 安装版检查地图本地装载、无 CS2/源码目录依赖及资源释放。自动验证、人工观察、未执行项目分别记录。
7. 记录导入/首帧/seek 耗时、峰值内存、缓存与 IPC 数据量，并与 P6.0 固定预算比较；不得把目标性能写成测量结果。

缺少强制真实 fixture 或资源/部署条件时，明确报告阻塞与可验证部分，不伪造 PASS，不为补样本自动下载比赛 DEM，也不擅自安装 CS2。开发所需纯合成边界测试可独立执行，但不能替代真实数据/安装验收。

## 8. 调研来源与未验证事项

- [DepotDownloader](https://github.com/SteamRE/DepotDownloader)：Steam 内容下载的开源工具；本项目已验证固定 3.4.0 版本通过文件列表获取指定 manifest 的索引和所需分卷。
- [Source2Viewer / ValveResourceFormat](https://github.com/ValveResourceFormat/ValveResourceFormat)：开源 VPK/Source 2 资源提取工具。
- [cs2-map-icons 固定 commit](https://github.com/MurkyYT/cs2-map-icons/tree/9a22f424dab892f8fd59cec100029883c05e6116)：社区素材提取路径参考；本项目未执行其下载脚本。该版本 PNG 与本机 Valve 提取结果字节不同，未混用。
- [awpy-data](https://github.com/pnxenopoulos/awpy-data)、[版本包 2000930](https://github.com/pnxenopoulos/awpy-data/releases/tag/2000930)：已核对实际版本包，五张目标图片与本机固定 Valve manifest 提取结果逐字节相同，摘要见资源清单。实际应用使用本机配套提取的 overview；Dust2 只完成四区域配准，不能据此确认 DEM 地图版本或其他地图实战配准。
- [CS Demo Manager 2D viewer](https://cs-demo-manager.com/docs/guides/2d-viewer)：交互与楼层显示参考，不代表直接复用其代码或更换现有 parser。
- Valve Developer Community 的 SteamCMD/CS2 Dedicated Servers 页面本次读取返回 403；未找到并验证可直接使用的 Valve 独立雷达下载接口。官方内容来源与社区提取工具/发布渠道必须分别注明。
- 现有 [空间契约](./spatial-evidence.md)、[解析边界](./dem-parser.md)、[桌面报告](./desktop-report.md)、[架构](./architecture.md) 约束实施。历史验收状态以当前 [路线图](./roadmap.md) 和最新验收结论为准，不能因旧章节恢复已修复的阻塞。
