# P8 AI Coach 技术路线

日期：2026-10-15。状态：技术路线设计，尚未开始实现；本轮只更新文档，不创建运行时模块、数据库或模型调用。

## 1. 目标与范围

通过持续导入职业 DEM，把可核验经验沉淀为项目拥有的规则、案例与评测资产。不同 AI 模型读取同一套知识、证据和分析规范；模型切换无需重新整理知识，但效果必须分别验证。

- 产品目标：从用户的问题出发分析个人操作与决策，同时支持职业选手个人决策复盘。
- 首批范围：Dust2 的 1v1 残局；关注空间利用、选位、暴露时机、转移与道具选择。
- 长期方向：在证据和验证能力成熟后扩展地图及 1vN；不承诺唯一“完美方案”或未经校准的最优胜率。
- 手动补充报点、声音与主观已知信息后续再做。首版缺失信息明确标为未知，不默认选手知道全局敌情。
- 本文确定技术分层与演进顺序；具体样本字段、标注手册、评分阈值和 UI 在对应工作单元启动前另行定义。

## 2. 技术选择

| 方面 | 本阶段路线 | 边界 |
| --- | --- | --- |
| 语言与运行 | 沿用 TypeScript、pnpm、Electron 本地分析管线 | 不另建 Python 统计管线，不重复实现现有指标 |
| 学习方式 | 外部知识积累：证据提取、候选规律、审核、验证、版本发布 | 不以参数微调或强化学习作为首版前提；导入 DEM 不等于模型权重更新 |
| 持久化 | 本地 SQLite 保存案例、候选规律、审核记录、规则版本与评测运行 | 知识库不等于未来账号下的比赛历史库；不引入账号或服务端数据库 |
| 可迁移资产 | Prompt 使用 Markdown；正式规则、知识快照和评测配置使用有版本的 JSON | SQLite 为运行与查询存储，已发布知识以不可变快照导出，记录校验摘要；不维护无版本的双份真相 |
| 检索 | 结构化条件过滤与适用条件匹配，必要时辅助全文检索 | 不以相同地点名称或最近坐标代替决策理解；向量检索不作为首版依赖 |
| 模型接入 | 应用自有的模型适配接口与统一 JSON 输入输出契约 | 不把规则写进厂商专属记忆；SDK、接口地址、密钥和能力差异留在适配层 |
| 地图推理 | 本地地图版本、坐标映射、拓扑与经验证的几何查询 | 2D 图像不能证明 LOS，导航连通也不能证明可见或安全 |
| 结果展示 | Fluent UI v9，复用回合证据跳转及 P6 回放入口 | AI 建议与确定性 Findings 分开展示，不覆盖原始统计或原诊断 |

SQLite 具体 Node 绑定、Electron 打包方式、全文分词与检索效果需在实现前做兼容性验证；本次不引入依赖。若数据库绑定不能通过 Windows 安装版验证，应记录阻塞并重新选择绑定，不绕过存储或安全边界。

## 3. 两条独立链路

### 3.1 知识积累链路

开始候选归纳前，P8.1 必须先完成来源去重、数据分组、保留集隔离及首轮评测协议冻结。归纳链路只能访问知识开发集；开发评测反馈可用于修订，但独立保留集不得用于生成或修订规则。

1. 用户主动导入职业 DEM，本地解析并记录来源、文件摘要、地图版本、解析器版本及覆盖情况。
2. 使用领域状态与确定性证据提取决策片段；有歧义或缺证据时不制造完整局面。
3. 代码统计与 AI 辅助归纳形成候选规律，关联支持案例、反例、条件和未知项。
4. 由具备游戏判断能力的人工审核，检查结果偏差、信息泄漏、替代解释和适用边界；AI 自评仅作辅助。
5. 在开发评测集上检验与修订，通过独立保留集发布门槛后形成正式知识版本。
6. 记录发布与撤销历史，允许回滚。新增 DEM 不直接改写系统 Prompt 或正式规则。

候选规律、已审核规则、已发布知识版本和已废弃内容必须区分。比赛获胜、职业身份、案例数量或模型自信都不能单独证明规律正确。规则版本要能追溯原始证据和反例；地图或规则版本变化时重新检查适用性。

### 3.2 个人复盘链路

1. 本地 DEM → 现有 Match、Analytics、Deep Review、Findings，以及经过独立验证的新空间证据。
2. 构建决策时刻的信息视图，隔离未知敌情和未来结果；事实、推断、假设分别标识。
3. 根据时间、炸弹状态、资源、空间关系和知识适用条件加载相关已发布规则；案例用于说明与反证。
4. 应用按固定预算组装 Prompt、当前证据、相关规则与必要案例；不把整个数据库或整场 tick 数据送入模型。
5. 模型提出处理方案、依据、成立条件、风险和待确认因素；允许给出多个合理分支或说明无法判断。
6. 本地校验结构、引用、数值、信息边界与可验证的空间约束；不通过则保留确定性报告，抑制相应 AI 输出。
7. 保存本次知识版本、Prompt 版本、模型标识、输入摘要与校验结果，便于复现和比较。

输出结构、引用格式和解析由应用保证；供应商支持的结构化输出或工具调用属于可选增强。无原生工具调用的模型可接收应用预先查询的相同证据。模型能力不足或输出校验失败时不承诺可用分析结果。

## 4. Prompt、知识与事实的职责

| 资产 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 固定 Prompt | 分析顺序、证据引用、未知项处理、输出格式 | 无限累积职业案例或伪装长期记忆 |
| 规则库 | 带条件、例外、支持与反对证据的决策原则 | 把一次成功操作升级为普遍结论 |
| 案例库 | 实际局面、行为、后续结果、来源和审核意见 | 用最终胜负直接标注当时选择的正确性 |
| 地图与计算工具 | 经过验证的空间、时间和资源事实 | 推测选手意图、听到的信息或敌人必然行为 |
| AI 模型 | 结合事实与规则解释，提出条件性方案 | 重新计算核心统计或自行发布规则 |

检索是知识装载机制，不能证明模型理解了决策。通用原则需围绕掩体关系、暴露方向、资源和时间约束表达；地图身份与几何仍须准确，跨地点泛化必须经测试。

## 5. 空间与信息能力门槛

- 现有 `MatchSpatialEvidence` 是事件附近的稀疏采样，不能当作完整移动轨迹、连续暴露过程或完整热力图。P6/P7 需各自设计并验证采样；保留实际 tick、缺失段与覆盖信息。
- P6 的 2D 回放提供观察与证据定位基础；P7 提供经过验证的分布统计。热力图不是残局最优决策的依据，也不构成 P8 所有能力的硬性技术依赖。
- 理解掩体、暴露角度和可行路线还需要独立的地图几何/拓扑能力验证。地图资产来源、合法使用、版本对应、坐标转换、静态遮挡与动态烟雾/门等状态必须分别处理。
- 地图几何获取与转换工具尚未选定。在该验证通过前，不提供“这条路线安全”“此处不会被看见”之类的确定性结论；2D 图或模型视觉判断不能补成已验证事实。
- 全局敌人真实位置可供事后事实核验，不能直接进入当时决策输入。几何 LOS 也不等于选手实际感知；无法可靠恢复的报点、声音和已知位置保持未知。
- 没有可靠动作、速度与时序证据时，不评价停枪质量、反应时间、精准瞄准等机械操作；同 tick 与缺失状态继续保留歧义。

## 6. 模块与安全边界

以下是逻辑职责，具体包名与接口在实施设计时确定，不在文档阶段创建抽象或更改公共 API。

- `dem-parser`：唯一 native DEM 查询适配入口，负责所需新采样及来源映射。
- `match-model`：共享领域事实与正式空间契约；新增领域契约仍按领域模型工作流处理。
- `analytics / deep-review / findings`：纯确定性计算与已验证诊断，不访问数据库、网络或模型。
- 本地知识存储与检索：管理案例、候选规律、规则发布和只读知识快照；不解析 DEM 或重新计算指标。
- 教练编排：消费公共证据、知识与地图查询结果，构建有信息边界的请求；领域核心不反向依赖编排层。
- 模型适配：处理供应商协议、超时、取消、重试和能力检测；密钥与网络调用不进入 Renderer。
- Desktop presenter / report-contract：按需新增经校验的 JSON 展示 DTO；React 只展示，不推导诊断或调用 native/parser。

如候选规律需要升级为可检测的新诊断，应先走“规则定义 → 证据契约 → 确定性实现 → 验证 → 解释”流程。自然语言原则本身不授权 AI 新增确定性 Findings、技能评分或因果归责。

DEM、完整轨迹和知识库存储在本地。云端模型只接收为当前请求组装的必要证据与知识片段；应用需明确显示外发内容范围，具体设置在接入时设计。离线模型可通过相同接口消费这些数据。当前无模型网络调用，也无服务端 DEM 分析。

输入的玩家昵称、导入备注、案例文本和模型回复均为数据，不能覆盖系统规则、触发任意 SQL/代码执行或发布知识。检索查询与允许的工具由应用控制。

## 7. 验证路线

这里只定义验证机制，不在本轮确定样本字段和评分量表，也不启动采集或评测。

1. 按完整比赛及其来源分组划分知识开发集、开发评测集和独立保留集；同一 DEM、重复下载、同一残局邻近片段不得跨集合。
2. 决策输入截止于决策时刻；后续结果和全局隐藏信息放入隔离的评测材料，不让模型或检索链路读到。
3. 用相同模型对比无职业知识与有已发布知识的结果，再用固定知识版本、相同证据比较不同模型；记录输入预算与重复运行，避免把随机性当成改进。
4. 程序校验事实引用、数值、结构和已支持的几何约束；人工评审决策合理性、条件、风险与替代方案。裁判模型不得作为唯一通过依据。
5. 对未见地点组合及局势做泛化检查；增加信息缺失、规则冲突和适用条件不满足的样本，检查是否正确保留未知或拒绝结论。
6. 发布门槛、评审量表和样本数量在评测工作单元开始前固定。保留集失败后的定向修改只能在新保留集上重新证明泛化，原失败结果不得抹去。
7. 每次知识或 Prompt 变更运行固定回归；已发布版本保持不可变。若引用造假、泄漏隐藏信息或输出无法支持的确定性结论，则该输出不能发布。

没有可靠模拟环境或受控实验时，不给未发生的路线编造胜率，不声称建议因果上优于实际行动。文字建议的审核通过不等于实战胜率提升；后者需要独立验证。

| P7 地图热力图 | 设计空间统计采样、口径、覆盖与展示，复用可验证的地图基础 | 未开始 |

| P8.2 知识积累 | 建立案例/规则存储、人工审核、知识快照与撤销机制；开展有边界的候选归纳 | 未开始 |
| P8.3 独立评测 | 按已冻结的样本定义、量表、集合与发布门槛运行基线比较和独立评测，发布首个通过门槛的快照 | 未开始 |
